# RhinoCAM G-code Automation

Проект для Rhino 8 + RhinoCAM 2025. Скрипты подготавливают геометрию по листам `List_*`, создают RhinoCAM `Setup` для каждого листа, формируют операции обработки и сохраняют G-code.

## Как Работает

1. `Geometry to layers.py` подготавливает слои `List_1`, `List_2`, `List_3` и т.д.
2. `main.py` запускается из RhinoCode как короткая точка входа.
3. `cam/job.py` находит кривые на слоях `List_*`.
4. Для каждого листа создается отдельный RhinoCAM `Setup`.
5. Внутри setup создаются операции:
   - `Nacolka`
   - `Skvoz_D5`
   - `Vyborka_D8_D9_D35_Z13`
   - `Vyborka_Inside_Kontur_Z13`
   - `Kontur`
6. Для каждого setup создается один общий файл УП:

```text
GCode/List_1.nc
GCode/List_2.nc
GCode/List_3.nc
```

## Назначение Файлов И Папок

### Основная Логика

`main.py` - короткий стартовый файл. Его запускают из RhinoCode; он находит корень проекта и передает управление в `cam/job.py`.

`Geometry to layers.py` - подготовительный скрипт для Rhino. Раскладывает исходные кривые по слоям `List_1`, `List_2`, `List_3` и создает направляющие прямоугольники.

**cam/** - основная логика RhinoCAM-обработки.

`cam/job.py` - основной сценарий: находит кривые, создает `Setup`, добавляет операции и делает один G-code файл на каждый лист.

`cam/classification.py` - определяет тип кривых по размеру: наколка, сквозные отверстия, выборки и внешний контур.

`cam/config.py` - размеры, глубины обработки и пути к выходным файлам.

`cam/operations.py` - низкоуровневая настройка RhinoCAM MOp: глубина, сторона реза, подачи, регенерация траектории.

**cam/tools/** - параметры режущих инструментов.

`cam/tools/tool_D3.json` - текущий инструмент: фреза D3.

**geometry/** - работа с Rhino-геометрией.

`geometry/curves.py` - поиск кривых, расчет bounding box и краткое описание кривой.

**plugins/** - тонкие обертки над Rhino и RhinoCAM API.

`plugins/rhino8.py` - операции Rhino: выбор объектов, слой объекта, безопасное имя файла.

`plugins/rhinocam.py` - операции RhinoCAM API: инициализация, инструмент, stock, setup, post-process.

### Общие Служебные Модули

**core/** - общие функции, которые используются основной логикой, но не завязаны напрямую на создание MOp.

`core/project.py` - поиск корня проекта, особенно важен при запуске из временной папки RhinoCode.

`core/layers.py` - фильтрация и порядок слоев `List_*`.

`core/files.py` - поиск созданного G-code файла и переименование в имя setup.

`core/logging_utils.py` - вывод сообщений в терминал RhinoCode и запись в `rhinocam_main.log`.

### Данные И Результаты

**data/** - исходные данные проекта.

**data/models/** - Rhino-модели `.3dm`.

**GCode/** - результат работы скрипта: готовые `.nc` файлы. Папку можно очищать перед новым тестом.

`rhinocam_main.log` - лог последнего запуска `main.py`.

### Документация И Примеры

**docs/** - дополнительная документация по проекту.

`docs/PROJECT_STRUCTURE.md` - краткая карта текущей структуры проекта.

`docs/FILES_AND_FOLDERS.md` - отдельная справка по назначению файлов и папок.

**examples/** - примеры ранее полученных УП для сравнения.

**archive/** - старые пробные версии скриптов, оставлены как история и запасной материал.

**archive/probnic/** - прежние монолитные и пробные версии `Project2*.py`.

### Вспомогательное

**tools/** - вспомогательные скрипты для разработки, не основной запуск RhinoCAM.

`tools/tmp_read_sdk_pdf.py` - временный скрипт для чтения/исследования SDK-документации.

**__pycache__/** - служебный кэш Python. Его можно не трогать; он не нужен для понимания проекта.

`.gitignore` - список файлов и папок, которые не нужно хранить в git: кэш, логи, сгенерированные УП.

`~$README.md` - временный файл блокировки редактора/Office/синхронизации. Это не часть проекта, его можно игнорировать.

## Запуск

1. Открой Rhino 8 с RhinoCAM 2025.
2. Запусти `Geometry to layers.py`, если нужно разложить исходную геометрию по слоям `List_*`.
3. Удали старые `Setup` в RhinoCAM перед чистым тестом.
4. Убедись, что выбран нужный postprocessor RhinoCAM.
5. Запусти `main.py` из RhinoCode.

После успешного запуска в RhinoCAM появятся setup по листам, а файлы УП будут сохранены в `GCode/`.

## Правила Обработки

- Обрабатываются только слои вида `List_1`, `List_2`, `List_3`.
- Порядок setup управляется в `core/layers.py`.
- Все операции одного листа объединяются в одну УП по имени setup.
- Имя файла берется из имени setup: `List_1.nc`, `List_2.nc`.
- Глубина основного реза: `16 мм`.
- Верх реза: `Z=0`.
- Наколка `3 мм`: глубина `2 мм`.
- Выборки `8/9/35 мм`: глубина `13 мм`.

```text

```

Здесь меняются стратегии `nacolka`, `vyborka`, `skvoznoe`, `raskroy`, общий `SPINDLE_RPM`, припуски по УП и припуски по стратегии.

Настройки RhinoCAM-операций:

```text
cam/operations.py
```

Основной сценарий создания setup и G-code:

```text
cam/job.py
```

### Памятка По CAM-Параметрам

Основной файл для настройки:

```text
cam/config.py
```

В обычной работе параметры меняются именно здесь. В `cam/operations.py` лезем только если нужно изменить сам способ применения параметров к RhinoCAM API.

1. Параметры движения фрезы: скорость реза, подход, врезание, отвод

   Файл:

   ```text
   cam/config.py
   ```

   Блок:

   ```python
   STRATEGIES = {
       "nacolka": {...},
       "vyborka": {...},
       "skvoznoe": {...},
       "raskroy": {...},
   }
   ```

   Основные поля:

   ```python
   plunge_feed = 300.0      # подача врезания
   approach_feed = 400.0    # подача подхода
   engage_feed = 400.0      # подача входа в рез
   cut_feed = 800.0         # рабочая подача реза
   retract_feed = 1000.0    # подача отвода
   departure_feed = 1000.0  # подача выхода
   ```

   Применяются в функции:

   ```python
   apply_feed_params()
   ```

2. Толщина съема материала за один проход

   Файл:

   ```text
   cam/config.py
   ```

   Поле внутри нужной стратегии:

   ```python
   step_down = 4.0
   ```

   Это глубина прохода по Z. В RhinoCAM передается через:

   ```python
   SetRoughCutDepthPerCut
   ```

3. Припуск, например `0.1` или `-0.1`

   Припуск по умолчанию задается внутри каждой стратегии:

   ```text
   cam/config.py
   ```

   Пример:

   ```python
   "raskroy": {
       "stock_allowance": 0.0,
   }
   ```

   Припуск для всей конкретной УП:

   ```python
   STOCK_ALLOWANCE_BY_UP = {
       "List_1": 0.1,
       "List_2": -0.1,
   }
   ```

   Припуск для конкретной стратегии внутри одной УП:

   ```python
   STOCK_ALLOWANCE_BY_UP_AND_STRATEGY = {
       ("List_1", "raskroy"): 0.1,
       ("List_2", "vyborka"): -0.1,
   }
   ```

   Выбор припуска выполняется функцией:

   ```python
   stock_allowance_for()
   ```

   Применение к RhinoCAM MOp находится в:

   ```text
   cam/operations.py
   ```

   Функция:

   ```python
   apply_stock_allowance_params()
   ```

4. Направление движения: по часовой или против

   Файл:

   ```text
   cam/config.py
   ```

   Поле внутри нужной стратегии:

   ```python
   "cut_direction": "climb"
   ```

   Значения:

   - `"climb"` - движение по часовой стрелке
   - `"conventional"` - движение против часовой стрелки

5. Обороты шпинделя

   Общий параметр для всех УП:

   ```text
   cam/config.py
   ```

   Поле:

   ```python
   SPINDLE_RPM = 18000.0
   ```

   Применение к RhinoCAM MOp находится в:

   ```text
   cam/operations.py
   ```

   Функция:

   ```python
   apply_spindle_params()
   ```

## Примечание

`main.py` специально оставлен в корне проекта. RhinoCode запускает скрипты из временной staging-папки, поэтому входной файл сначала добавляет корень проекта в `sys.path`, а затем вызывает `cam.job.run()`.
