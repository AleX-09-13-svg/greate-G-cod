# RhinoCAM G-code Automation

Проект для Rhino 8 + RhinoCAM 2025. Скрипты подготавливают геометрию по листам `List_*`, создают RhinoCAM `Setup` для каждого листа, формируют операции обработки и сохраняют G-code.

## Как Работает

1. `01Geometry to layers.py` подготавливает слои `List_1`, `List_2`, `List_3` и т.д.
2. `02GeometryToZerro.py` при необходимости сдвигает геометрию листов к рабочему нулю.
3. `03main.py` запускается из RhinoCode как основная рабочая точка входа.
4. `cam/job.py` находит кривые на слоях `List_*`.
5. Для каждого листа создается отдельный RhinoCAM `Setup`.
6. Внутри setup создаются операции:
   - `Nacolka`
   - `Skvoz_D5`
   - `Vyborka_D8_D9_D35_Z13`
   - `Vyborka_Inside_Kontur_Z13`
   - `Kontur`
7. Для операций явно задается `Stock = 0.0`.
8. Перед сохранением открывается выбор папки для G-code.
9. Для каждого setup создается один общий файл УП:

```text
<выбранная папка>/List_1.nc
<выбранная папка>/List_2.nc
<выбранная папка>/List_3.nc
```

## Назначение Файлов И Папок

### Основная Логика

`01Geometry to layers.py` - подготовительный скрипт для Rhino. Раскладывает исходные кривые по слоям `List_1`, `List_2`, `List_3` и создает направляющие прямоугольники.

`02GeometryToZerro.py` - вспомогательный скрипт: сдвигает геометрию слоев `List_*` к рабочему нулю по X.

`03main.py` - основной рабочий стартовый файл. Его запускают из RhinoCode; он находит корень проекта, задает `Stock = 0.0` для стратегий и передает управление в `cam/job.py`.

`04_save_G_cod.py` - отдельный модуль сохранения G-code для уже готовых RhinoCAM setup. Его можно запускать отдельно из RhinoCode, если setup уже созданы в текущей RhinoCAM-сессии. Скрипт сам находит корень проекта при запуске через временную папку RhinoCode, выбирает папку для УП, синхронизирует RhinoCAM database, ищет setup и сохраняет один `.nc` файл на каждый setup.

`rhino_bootstrap.py` - общий bootstrap-модуль для `03main.py` и `04_save_G_cod.py`. Он ищет корень проекта при запуске из временной папки RhinoCode, добавляет его в `sys.path` и обновляет кэш импортов.

**cam/** - основная логика RhinoCAM-обработки.

`cam/job.py` - основной сценарий: находит кривые, создает `Setup`, добавляет операции и делает сохранение G-code через модуль `04_save_G_cod.py`.

`cam/classification.py` - определяет тип кривых по размеру: наколка, сквозные отверстия, выборки и внешний контур.

`cam/config.py` - размеры, глубины обработки и пути к выходным файлам.

`cam/operations.py` - низкоуровневая настройка RhinoCAM MOp: глубина, сторона реза, подачи, регенерация траектории.

**cam/tools/** - параметры режущих инструментов.

`cam/tools/tool_D3.json` - текущий инструмент: фреза D3.

**geometry/** - работа с Rhino-геометрией.

`geometry/curves.py` - поиск кривых, расчет bounding box и краткое описание кривой.

**plugins/** - тонкие обертки над Rhino и RhinoCAM API.

`plugins/rhino8.py` - операции Rhino: выбор объектов, слой объекта, безопасное имя файла.

`plugins/rhinocam.py` - операции RhinoCAM API: инициализация, инструмент, stock, setup, post-process. Для RhinoCAM 2025 setup читаются через `GetMOpSetupCount`, `GetMOpSetupByIndex` и `GetMOpSetupName`.

### Общие Служебные Модули

**core/** - общие функции, которые используются основной логикой, но не завязаны напрямую на создание MOp.

`core/project.py` - уточнение корня проекта после первичного bootstrap.

`core/layers.py` - фильтрация и порядок слоев `List_*`.

`core/files.py` - низкоуровневые функции для снимка папки, поиска созданного G-code файла и переименования.

`core/logging_utils.py` - вывод сообщений в терминал RhinoCode и запись в `rhinocam_main.log`.

## Запуск

1. Открой Rhino 8 с RhinoCAM 2025.
2. Запусти `01Geometry to layers.py`, если нужно разложить исходную геометрию по слоям `List_*`.
3. При необходимости запусти `02GeometryToZerro.py`, чтобы сдвинуть листы к рабочему нулю.
4. Удали старые `Setup` в RhinoCAM перед чистым тестом.
5. Убедись, что выбран нужный postprocessor RhinoCAM.
6. Запусти `03main.py` из RhinoCode.
7. В появившемся окне выбери папку для сохранения G-code. Если папку не выбрать, используется `GCode/` в корне проекта.

После успешного запуска в RhinoCAM появятся setup по листам, а файлы УП будут сохранены в выбранную папку.

### Отдельное Сохранение УП Через `04_save_G_cod.py`

`04_save_G_cod.py` нужен, когда RhinoCAM setup уже есть в текущем открытом файле, а нужно только заново выгрузить УП.

Порядок:

1. Открой Rhino-файл, где уже есть RhinoCAM setup.
2. Убедись, что выбран нужный postprocessor RhinoCAM.
3. Запусти `04_save_G_cod.py` из RhinoCode или через `RunPythonScript`.
4. Выбери папку для сохранения УП.
5. Проверь вывод RhinoCode.

Нормальный вывод выглядит так:

```text
04_save_G_cod bootstrap 2026-10-06 02 from ...
G-code output dir: ...
RhinoCAM setups found: 1
G-code saved by PostProcessSetup: ...\List_1.nc
```

Если выводит `RhinoCAM setups found: 0`, значит `04_save_G_cod.py` не видит setup в текущей RhinoCAM-сессии. В этом случае сначала создай setup через `03main.py` или проверь, что открыт правильный Rhino-файл. Диагностическая строка `Setup discovery: ...` показывает, что реально возвращает RhinoCAM API.

## Правила Обработки

- Обрабатываются только слои вида `List_1`, `List_2`, `List_3`.
- Порядок setup управляется в `core/layers.py`.
- Все операции одного листа объединяются в одну УП по имени setup.
- Имя файла берется из имени setup: `List_1.nc`, `List_2.nc`.
- Поле RhinoCAM `Stock` в операциях явно устанавливается в `0.0`.
- Глубина основного реза: `16 мм`.
- Верх реза: `Z=0`.
- Наколка `3 мм`: глубина `2 мм`.
- Выборки `8/9/35 мм`: глубина `13 мм`.

### Памятка По CAM-Параметрам

Основной файл для настройки:

```text
cam/config.py
```

В обычной работе параметры меняются именно здесь. В `cam/operations.py` лезем только если нужно изменить сам способ применения параметров к RhinoCAM API.

1. Параметры движения фрезы: скорость реза, подход, врезание, отвод

   Файл:

   ```text
   cam/config.py
   ```

   Блок:

   ```python
   STRATEGIES = {
       "nacolka": {...},
       "vyborka": {...},
       "skvoznoe": {...},
       "raskroy": {...},
   }
   ```

   Основные поля:

   ```python
   plunge_feed = 300.0      # подача врезания
   approach_feed = 400.0    # подача подхода
   engage_feed = 400.0      # подача входа в рез
   cut_feed = 800.0         # рабочая подача реза
   retract_feed = 1000.0    # подача отвода
   departure_feed = 1000.0  # подача выхода
   ```

   Применяются в функции:

   ```python
   apply_feed_params()
   ```

2. Толщина съема материала за один проход

   Файл:

   ```text
   cam/config.py
   ```

   Поле внутри нужной стратегии:

   ```python
   step_down = 4.0
   ```

   Это глубина прохода по Z. В RhinoCAM передается через:

   ```python
   SetRoughCutDepthPerCut
   ```

3. Припуск, например `0.1` или `-0.1`

   Припуск по умолчанию задается внутри каждой стратегии:

   ```text
   cam/config.py
   ```

   Пример:

   ```python
   "raskroy": {
       "stock_allowance": 0.0,
   }
   ```

   Припуск для всей конкретной УП:

   ```python
   STOCK_ALLOWANCE_BY_UP = {
       "List_1": 0.1,
       "List_2": -0.1,
   }
   ```

   Припуск для конкретной стратегии внутри одной УП:

   ```python
   STOCK_ALLOWANCE_BY_UP_AND_STRATEGY = {
       ("List_1", "raskroy"): 0.1,
       ("List_2", "vyborka"): -0.1,
   }
   ```

   Выбор припуска выполняется функцией:

   ```python
   stock_allowance_for()
   ```

   Применение к RhinoCAM MOp находится в:

   ```text
   cam/operations.py
   ```

   Функция:

   ```python
   apply_stock_allowance_params()
   ```

   В текущем рабочем запуске `03main.py` дополнительно принудительно ставит всем стратегиям:

   ```python
   stock_allowance = 0.0
   ```

   В логе успешное применение выглядит так:

   ```text
   [RhinoCAM main] SetStock set to 0.0
   ```

4. Направление движения: по часовой или против

   Файл:

   ```text
   cam/config.py
   ```

   Поле внутри нужной стратегии:

   ```python
   "cut_direction": "climb"
   ```

   Значения:

   - `"climb"` - движение по часовой стрелке
   - `"conventional"` - движение против часовой стрелки

5. Обороты шпинделя

   Общий параметр для всех УП:

   ```text
   cam/config.py
   ```

   Поле:

   ```python
   SPINDLE_RPM = 18000.0
   ```

   Применение к RhinoCAM MOp находится в:

   ```text
   cam/operations.py
   ```

   Функция:

   ```python
   apply_spindle_params()
   ```

## Примечание

`03main.py` специально оставлен в корне проекта. RhinoCode запускает скрипты из временной staging-папки, поэтому входной файл сначала добавляет корень проекта в `sys.path`, а затем вызывает `cam.job.run()`.
